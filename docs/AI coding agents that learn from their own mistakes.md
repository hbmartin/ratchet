# AI coding agents that learn from their own mistakes

**The feedback loop where an AI coding agent's failures and successes automatically become training signal for its future behavior is now partially realized in both research and production — but no system fully closes this loop.** Foundational 2023 work established three core patterns: storing successful procedures as reusable skills (Voyager), extracting verbal decision rules from failures (Reflexion), and distilling cross-task strategies from experience pools (ExpeL). By 2025-2026, these patterns have migrated into production coding tools — Claude Code's Auto Memory system writes and consolidates notes from its own sessions, GitHub Copilot's cross-agent memory learns repository conventions without explicit instructions, and self-modifying agents like the Darwin Gödel Machine have evolved themselves from **20% to 50% on SWE-bench** purely through autonomous scaffold editing. Yet a landmark 2026 evaluation found that skill benefits are fragile under realistic retrieval conditions, and the hardest problems — skill generalization, strategy conflicts, and quality assurance — remain substantially unsolved.

## Three foundational patterns emerged in 2023

The paradigm crystallized around three complementary systems, each solving a different part of the feedback loop. **Voyager** (Wang et al., 2023; NVIDIA/Caltech) built the first growing skill library for an LLM agent, operating in Minecraft but establishing an architecture directly applicable to coding. Skills are stored as **executable JavaScript functions** indexed by text embeddings of their descriptions, retrieved via cosine similarity when the agent encounters a new task. Complex skills compose simpler ones — `craftDiamondPickaxe()` calls `mineIronOre()` which calls `craftWoodenPickaxe()`. A self-verification loop where GPT-4 acts as critic determines whether a skill succeeded before adding it to the library, eliminating human labeling. The result: **15.3x faster** milestone completion than baselines, with the skill library transferring zero-shot to entirely new Minecraft worlds.

**Reflexion** (Shinn et al., NeurIPS 2023) solved a different problem — extracting decision rules from failure. After a failed attempt, the LLM generates a verbal self-reflection ("semantic gradient") analyzing what went wrong and how to fix it. These reflections accumulate in an episodic memory buffer (capped at the last 3) that conditions all subsequent attempts. Applied directly to coding benchmarks, Reflexion achieved **91% pass@1 on HumanEval** using compiler errors and test pass/fail as its sole automatic supervision signal. The limitation is fundamental: Reflexion learns within a single task. It gets better at solving problem X through retries, but insights from problem X don't transfer to problem Y.

**ExpeL** (Zhao et al., AAAI 2024; Tsinghua) closed this gap with cross-task learning. Its three-stage pipeline — experience gathering via Reflexion-style retries, insight extraction by comparing failed vs. successful trajectories, and inference using both extracted insights and retrieved successful examples — generates generalizable natural language rules like "when looking for items in a kitchen, check drawers before counters." An evolving insight set uses four operations — **ADD, UPVOTE, DOWNVOTE, EDIT** — to maintain and refine knowledge over time. ExpeL matches Reflexion's performance without needing multiple retries at test time, demonstrating genuine transfer learning from one task to another.

**LATS** (Zhou et al., ICML 2024) added search, modeling agent decision-making as Monte Carlo Tree Search where the LLM serves simultaneously as action generator, value function, and reflector. Failed trajectories produce reflections that context-condition all future search iterations. This achieved **92.7% pass@1 on HumanEval** but at substantially higher computational cost — exploring a full search tree requires far more LLM calls than linear approaches.

## Self-modifying agents now rewrite their own code

The most striking 2025-2026 development is agents that improve not by accumulating external memories but by editing their own source code. **SICA** (Robeyns et al., ICLR 2025 Workshop; University of Bristol) maintains an archive of its own prior versions with benchmark scores. At each iteration, it selects the best-performing version as both meta-agent and task-solver, then autonomously modifies its scaffolding code — adding diff-based editing tools, AST symbol locators, and reasoning sub-agents it invented for itself. Performance jumped from **17% to 53%** on a SWE-Bench Verified subset through pure self-modification without any weight updates.

The **Darwin Gödel Machine** (Zhang et al., 2025; Sakana AI) extended this with evolutionary diversity. Instead of hill-climbing from the best agent, DGM maintains a branching archive where any agent — including suboptimal "ancestors" — can seed new lineages. Over approximately two weeks and **~$22,000 in API costs**, DGM evolved from 20.0% to 50.0% on SWE-bench. Remarkably, self-discovered features like multi-solution generation with ranking and long-context window management transferred across different underlying LLMs, and a variant optimized only on Python tasks showed gains on Rust, C++, and Go.

**Live-SWE-agent** (Xia et al., 2025; UIUC) pushed this further by evolving at runtime rather than between benchmark runs. Starting from minimal shell tools, it modifies its own methods, classes, and tool definitions during live problem-solving episodes, validating each upgrade with mini-integration tests. This achieved **79.2% on SWE-bench Verified** with Claude Opus 4.5 — the highest score among open-source scaffolds.

On the trajectory-learning side, **SWE-Gym** (Pan et al., ICML 2025; Berkeley) demonstrated that fine-tuning on just **491 successful agent trajectories** yields +12.3% improvement on SWE-Bench Lite, using test pass/fail as the sole automatic reward. The key finding: training dramatically reduces "stuck-in-loop" behavior where agents repeat the same failed approach, suggesting that execution traces contain learnable signals about when to switch strategies.

## Production systems have partially closed the loop

Among commercial coding agents, **Claude Code has the most mature learning-from-experience system**. Its Auto Memory feature (introduced in v2.1.59+) autonomously writes notes during sessions — build commands that worked, debugging insights, architecture observations, code style preferences — and stores them in MEMORY.md files capped at ~200 lines. An **Auto Dream** consolidation system, analogous to memory consolidation during sleep, periodically reviews all memory files, prunes stale entries, resolves contradictions, and reorganizes into clean indexed topic files. This runs automatically after configurable triggers (default: 24 hours plus 5 sessions). A separate Skills system stores reusable multi-step workflows as SKILL.md files with progressive disclosure — only ~100 tokens of metadata load at startup, with full instructions loading on-demand. Community extensions like Claude Diary add explicit reflection loops that analyze session logs and update persistent instructions.

**GitHub Copilot's cross-agent memory**, announced in public preview, represents the most architecturally ambitious approach. Different Copilot agents — coding, code review, CLI — contribute to and benefit from a shared per-repository knowledge base. When Copilot code review discovers a logging convention, the coding agent applies it when building new services, and the CLI agent uses it for debugging. Each agent validates memories before acting on them, and the system handles the hard problem of memory validity as code evolves across branches. GitHub's blog describes this as learning "without relying on explicit user instructions."

**Windsurf** autonomously generates and stores memories during conversations when its Cascade agent encounters context worth remembering. However, its own documentation acknowledges reliability limitations: "For knowledge you want Cascade to reliably reuse, write it as a Rule rather than relying on auto-generated Memories." **Devin** offers Session Insights that analyze completed sessions and provide improvement recommendations, plus a Knowledge system and Playbooks, but these remain primarily human-curated. **Cursor** has no automatic learning mechanism — its `.cursor/rules/` system is entirely manual, and the popular "Memory Bank" pattern is a community workaround, not a native feature. **Amazon Q Developer** and **Aider** are explicitly stateless between sessions.

The **Agent Skills Specification**, released by Anthropic in December 2025 and adopted by OpenAI for Codex CLI, standardized the format for modular SKILL.md packages. This catalyzed an ecosystem — marketplaces like agentskill.sh accumulated **44,000+ skills** within months — but the skills are manually authored, not automatically distilled from execution traces. The infrastructure is ready; the automatic distillation layer is the missing piece.

## How skills and strategies are stored, retrieved, and injected

Five distinct storage architectures have emerged. **Executable code libraries** (Voyager pattern) store skills as callable functions — maximally concrete, composable, and testable, but domain-specific. **Markdown skill files** (SKILL.md pattern) use progressive disclosure — YAML frontmatter for discovery (~few dozen tokens), full body for activation, and resource subdirectories for deep reference. **Vector databases** (Mem0, A-MEM, ExpeL) embed memories as vectors for similarity retrieval, achieving **91% lower p95 latency** and 90% fewer tokens than full-context approaches. **Tiered memory** (MemGPT/Letta) mirrors OS virtual memory with core memory (always in-context), archival memory (infinite external storage), and recall memory (searchable conversation history), with the agent managing data movement via function calls. **Rule databases** (ExpeL pattern) maintain evolving natural language strategies with confidence scores adjusted through upvote/downvote mechanisms.

Retrieval has become increasingly sophisticated. Voyager's simple cosine similarity over skill embeddings has given way to multi-stage pipelines. **SkillFlow** (2026) uses a four-stage pipeline — dense retrieval, shallow reranking, deep reranking, LLM-based selection — to handle 36,000+ skills. A critical finding from **SkillRouter** (Zheng et al., 2026): the full skill body text is the decisive routing signal, with cross-encoder attention analysis showing **91.7% of attention** focused on implementation details rather than name or description. Removing the body causes 29-44 percentage point accuracy degradation, overturning the common assumption that metadata suffices for routing.

Injection into agent context follows four patterns: system prompt concatenation (simplest, used by Mem0 and ExpeL), few-shot example retrieval (ExpeL's successful trajectory recall), tool definition registration (skills as callable functions), and progressive disclosure (metadata-first loading with on-demand expansion). The progressive disclosure pattern is particularly important for scaling: it allows thousands of skills to be "installed" with minimal context overhead, loading full instructions only when triggered.

## The hardest problems remain substantially unsolved

**Skill benefits are fragile under realistic conditions.** A landmark 2026 study by Liu et al. ("How Well Do Agentic Skills Work in the Wild") evaluated 34,000 real-world skills across progressively challenging settings. In idealized conditions with hand-curated, task-specific skills pre-loaded, they found a substantial **+16.2 percentage point** improvement in pass rate. Under realistic conditions — where the agent must retrieve from the full 34K library without curation — performance **degraded to near no-skill baselines**. This held across Claude Opus 4.6, Kimi K2.5, and Qwen3.5-397B. The bottlenecks are twofold: agents struggle to decide which skills to load, and retrieved content is often noisy or imprecise.

**Skill selection hits a phase transition around 50-100 skills.** Li et al. (2026) demonstrated that selection accuracy remains stable below a critical threshold then drops sharply, driven by semantic confusability among similar skills — analogous to interference effects in human memory retrieval. Hierarchical routing (coarse-to-fine selection) maintains **72-85% accuracy** where flat selection degrades to 45-63%, suggesting that cognitive science's "chunking" concept applies directly to agent skill architectures.

**Strategy conflicts lack standardized resolution.** When an agent accumulates contradictory rules — "use PostgreSQL" alongside "we switched to MySQL" — systems handle this ad hoc. CrewAI's Cognitive Memory auto-detects contradictions via LLM analysis. ByteRover implements importance scoring with maturity tiers (draft → stable → archived) and automatic decay. But no system robustly handles the deeper case where two debugging strategies both work in different contexts, creating genuine ambiguity about which to apply.

**Quality assurance is a critical gap.** Analysis of 42,447 community-contributed skills found that **26.1% contain at least one security vulnerability**, with 5.2% exhibiting patterns suggesting malicious intent. The ClawHavoc campaign infiltrated a major marketplace with ~1,200 malicious skills exfiltrating API keys and cryptocurrency wallets. Unlike software packages with unit tests and CI/CD pipelines, skills currently lack standardized testing frameworks. Self-generated skills may actually degrade agent performance compared to no skills at all — the SoK paper on agent skills anchors its evaluation around the finding that curated skills substantially help while self-generated skills may hurt.

**Environmental drift** — where a stored skill becomes wrong because an API changed or a library updated — remains an open research challenge. No system robustly detects or handles this. **Catastrophic forgetting** at the weight level intensifies with model scale and is not reliably prevented by parameter-efficient methods like LoRA. Voyager's design explicitly sidesteps this by storing skills externally as code rather than in model weights, but this trades one problem (forgetting) for another (stale knowledge).

An underappreciated finding from recent work is that **failure-derived heuristics substantially outperform success-derived ones**. Experiential Reflective Learning (ERL, 2026) found that heuristics extracted from failed trajectories improved search task performance by **+14.3% over baseline**, significantly more than success-derived heuristics. AgentHER (2026) showed that failed trajectories — typically 60-85% of all agent runs — contain rich training signal that is routinely discarded. A trajectory that fails at goal A is often a correct demonstration for an achievable alternative goal B, enabling conversion of discarded failures into high-quality training data via hindsight relabeling.

## Conclusion

The field has converged on a clear architectural vision: agents should automatically distill their execution traces into reusable skills (successful procedures) and strategies (decision rules from corrections), store them in persistent memory with confidence-weighted maintenance, retrieve them via multi-stage pipelines, and inject them into future sessions through progressive disclosure. Each component of this vision has working implementations. Voyager proved skill libraries work. ExpeL proved cross-task strategy extraction works. Claude Code's Auto Memory and Auto Dream prove production-grade persistence and consolidation work. SWE-Gym proved that execution traces contain learnable signal.

What remains missing is the full integration. No production system automatically distills execution traces into verified, generalizable, retrievable skills without human involvement. The closest approximations — Claude Code's Auto Memory, GitHub Copilot's cross-agent memory — operate at the level of notes and conventions rather than verified executable procedures. The self-modifying agents (SICA, DGM, Live-SWE-agent) achieve impressive results but modify their own scaffolding code rather than building transferable skill libraries. The two most consequential open problems are retrieval quality at scale (the phase transition at ~50-100 skills) and skill verification (the 26% vulnerability rate in community skills). Solving these would unlock the full feedback loop — turning every coding session into automatic training data for the next one.
